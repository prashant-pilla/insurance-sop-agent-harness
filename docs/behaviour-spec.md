# Behaviour specification

Every rule the agent enforces, where it is implemented, which automated test pins it (file and what the test checks), which live scenario in `scripts/live_demo.py` shows it against a real model, and where the documentation explains it. "Design choice" marks a behaviour that could reasonably have gone another way; each one is stated under [Design decisions](../README.md#design-decisions) in the README.

Section names in the "Docs section" column are headings in [design.md](design.md) (Architecture and its freedom table, How the SOP gates work with its Identity, Memory, Scope, Emotion, Output guard and Injection resilience subsections, Representative consent flow, Design decisions and tradeoffs, Project layout) and [walkthroughs.md](walkthroughs.md) (Quick start, Try it), except "Configuration", "Design decisions" and "Roadmap", which are in the README, and "Example transcripts", which is [transcripts.md](transcripts.md).
